**Description** \
The agent needs to know which General Education (GE) requirements a student has already satisfied so it does not recommend GE courses they no longer need. Step 3 of the onboarding questionnaire (`client/src/pages/OnboardingPage.tsx`) currently asks the student to select their *remaining* GE requirements and pre-selects `CC` and `ER` by default. Most students don't know their remaining GEs offhand, and the pre-selection means the agent can receive answers the student never gave. This task changes the question so students check off the GE requirements they have *satisfied*, and adds on-screen instructions telling them where to find that information in their MyUCSC account. \
**Specs** \
As of sprint 4, Step 3 of the onboarding questionnaire should do the following:
 1. Ask the student to check off every GE requirement they have **already satisfied** (completed, transferred, or waived), with a prompt such as "Which GE requirements have you already satisfied?"
 2. Show one checkbox-style toggle per GE category, with the code and full name of each (e.g. `CC — Cross-Cultural Analysis`). Nothing is selected by default.
 3. Display an instruction panel on the same screen, above or beside the checklist, that tells the student how to look up their completed GEs:
    1. Log in to your **MyUCSC** account (https://my.ucsc.edu)
    2. Go to **My Academics**
    3. Click **Degree Progress Report** in the side navigation
    4. Scroll down to **General Education Requirements** and expand the tab
    5. Any requirement marked as satisfied or complete there should be checked off here
 4. Keep the existing **GE Fulfillment Source** selector (`UCSC` / `Community College / IGETC` / `Hybrid`) as it is.
 5. Let the student skip this step, consistent with the other questionnaire steps. A skipped step saves an empty completed list.

Data flow:
 1. Add a `geCategoriesCompleted: z.array(z.string()).default([])` field to `OnboardingQuestionnaireSchema` in `shared/src/onboarding.schema.ts`. It replaces `geCategoriesRemaining` as the field the student answers.
 2. In `server/src/services/progress.service.ts`, persist `ge_status` with both `completed` (the student's answers) and `remaining` (every GE category minus the completed ones). This keeps `query_degree_ge_requirements` in `agent_service/agent/tools.py`, which reads `geStatus.remaining`, working without changes. Add `completed` to that tool's output so the agent can reference it directly.
 3. Define the canonical list of GE categories once in `shared` and have both the client checklist and the server's `remaining` calculation import it. Do not keep separate copies in different places.

**Requirements** \
The GE category list must match the current UCSC General Catalog (https://catalog.ucsc.edu/en/current/general-catalog/undergraduate-information/undergraduate-academic-program/general-education-requirements): `CC`, `ER`, `IM`, `MF`, `SI`, `SR`, `TA`, `PE`, `PR`, `C`, `DC`. The current `GE_CATEGORIES` constant in `OnboardingPage.tsx` is missing `MF` (Mathematical and Formal Reasoning) and `DC` (Disciplinary Communication). `PE` / `PR` are each a single requirement satisfied by any one of their sub-areas (`PE-E`, `PE-H`, `PE-T` / `PR-C`, `PR-E`, `PR-S`), and Composition is a single `C` requirement. Make sure the labels and the remaining-GE calculation reflect this.
No GE category may be pre-selected. The agent must never treat a GE as satisfied unless the student checked it off.
The MyUCSC instructions must be visible without any extra click (no hover-only tooltip), and the MyUCSC link must open in a new tab.
The checklist must work with the keyboard and screen readers: each toggle needs an accessible label and must expose its checked state (e.g. `aria-pressed` or a real `<input type="checkbox">`).
Existing users who saved `geCategoriesRemaining` before this change must still load correctly. Either migrate those rows to `completed` = all − remaining, or fall back to reading `remaining` when `completed` is absent.
Follow the existing styling in `OnboardingPage.tsx` (Tailwind classes, `#00B4DB` accent for selected state). \

**Acceptance Criteria** \
The following types of tests should be in the test suite, and the code must pass all of them without lowering current coverage. Every test name starts with `GT22`; the full test plan is in `specs/004-ge-requirements/`.
- Schema: `OnboardingQuestionnaireSchema` accepts `geCategoriesCompleted`, defaults it to `[]`, and rejects non-string entries and unknown GE codes (`shared/tests/gt22.geRequirements.test.ts`).
- Server: submitting completed GEs `['CC', 'TA']` stores `ge_status.completed = ['CC', 'TA']` and a `remaining` list that contains every other category and neither `CC` nor `TA` (`server/tests/gt22.geProgress.test.ts`).
- Server: a skipped Step 3 stores `completed = []` and `remaining` equal to the full GE list.
- Server: a legacy user with only `geCategoriesRemaining` still returns a correct `geStatus`.
- Client: Step 3 renders the MyUCSC instruction steps in order, renders no pre-selected GE, and toggling a GE adds/removes it from `geCategoriesCompleted` (`client/tests/gt22.geChecklist.test.ts`).
- Agent: `query_degree_ge_requirements` returns both `remainingGEs` and `completedGEs`. When asked "What GEs do I still need?", the agent does not list any GE the student checked off (`agent_service/tests/test_gt22_ge_requirements.py`).
